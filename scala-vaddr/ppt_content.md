# 一、研究背景与动机（P3–P9，约4.5分钟）

## P3 存储墙问题

- 处理器计算速度持续增长，存储系统访问速度提升缓慢
- 访存延迟已成为制约处理器单线程性能的主要瓶颈——"存储墙"（Memory Wall）
- 三类应对手段：
  - 改进存储层次结构（更大缓存、更激进预取）
  - 提升访存并行度（更大发射宽度）
  - **缩短关键访存指令的执行路径延迟**（本文关注点）

## P4 装入指令的重要性与瓶颈

- 装入指令占动态指令比例高：20 个 SPEC CPU 基准实测平均 **25.3%**（含存储合计 **35.4%**）
- 装入指令位于数据依赖链根部，延迟沿依赖链逐级传播
- 即使 L1 D-Cache 命中，**发射队列排队延迟**仍是关键瓶颈：
  - 等待基址寄存器就绪 + 发射端口仲裁 + 读寄存器堆
  - 从进入发射队列到数据写回，最佳情况仍需 **5 个周期**

## P5 已有方案与不足

| 方案 | 思路 | 索引 | 是否推测 | 错误恢复 |
|------|------|------|---------|---------|
| Zero-Cycle Loads (1995) | 步进预测器预测装入地址 | PC | 是 | 需回滚 |
| LAP (Apple M2+) | 步进模式预测 | PC | 是 | 需回滚 |
| Register Tracking (ISCA 2000) | 跟踪寄存器值提前解析 | 寄存器号 | 否 | 需快照 |
| Constable (ISCA 2024) | 消除稳定装入指令 | PC | 否 | 需验证 |

已有方案的共性不足：
- PC 索引方案依赖预测 → 误预测需回滚，增加复杂度与性能波动
- Register Tracking 需维护快照用于分支恢复，存储开销大
- 均**未实现"命中即正确、无需错误恢复"**

## P6 存储相关预测与推测式调度

**存储相关预测：**

| 方案 | 思路 | 局限 |
|------|------|------|
| Store Sets (ISCA 1998) | 基于 PC 历史关联存储-装入对 | 基于历史统计，无法利用已知地址信息 |
| Alpha 21264 LWT | Load Wait Table 阻塞违例装入 | 控制流预测驱动，保守阻塞降低性能 |

**推测式调度：**
- BOOM V3 原有推测式唤醒仅覆盖从发射队列发射的装入指令
- 绕过发射队列的装入指令无法触发推测唤醒 → 依赖链收益受限

**小结：** 地址预测、冲突检测、推测唤醒三个维度缺乏统一的协同优化

## P7 核心观察与本文思路

**核心观察：** 装入指令的基址寄存器回写值可被译码阶段观测到

- 当装入指令完成执行回写时，基址值可以缓存在译码阶段可访问的映射表中
- 后续使用相同基址寄存器的装入指令，在译码阶段即可直接获取地址

**本文思路：** 在译码阶段维护寄存器 → 缓存行地址的映射表（Tracing Map），命中的装入指令绕过发射队列和读寄存器阶段，直接进入访存流水线

**关键特性：** 确定性地址获取，命中即正确，无需错误恢复

| 对比 | 本文 Tracing Map | 已有方案 |
|------|-----------------|---------|
| 索引 | 寄存器号（天然共享基址） | 多为 PC 索引 |
| 推测性 | 非推测，命中即正确 | 多为推测性预测 |
| 错误恢复 | 无需（分支误预测直接全部失效） | 需回滚/快照/验证 |

## P10 总体方案架构

四个子模块在流水线中的位置：

```
Decode:     Tracing Map 查表 → 命中？→ 标记地址已就绪
                                        ↓
Dispatch:   命中的装入绕过 IQ → 直接写入 LDQ + ROB
            SAB 检测存储-装入地址冲突
                                        ↓
LSU(Retry): 重试路径 → TLB → D-Cache → Writeback
            推测式唤醒扩展 → 提前唤醒依赖指令
                                        ↓
Writeback:  基址值回写更新 Tracing Map
```

递进逻辑：**基础功能 → 覆盖率扩展 → 安全性增强 → 收益放大**

## P11 Tracing Map 表结构

以**逻辑寄存器号**为索引，共 32 个条目

| 字段 | 位宽 | 说明 |
|------|------|------|
| Valid | 1 bit | 条目是否有效 |
| Waiting | 1 bit | 是否等待回写更新 |
| Waiting_num | 6 bit | 等待的装入指令序列号 |
| Base_value | 40 bit | 缓存的基址值 |

总存储开销：48 bit × 32 = **1536 bit (192 Byte)**

缓存行粒度：D-Cache 按缓存行寻址，同一缓存行内偏移不影响 TLB/Cache 命中

## P12 Tracing Map 查询流程（译码阶段）

**命中（Valid = 1）：**
1. 读取 Base_value
2. 计算 Vaddr = Base_value + Imm_offset
3. 标记装入指令"地址已就绪"→ 分发时绕过发射队列

**未命中（Valid = 0 且 Waiting = 0）：**
1. 设置 Waiting = 1，分配序列号
2. 装入指令按常规路径进入发射队列
3. 装入-存储部件完成后回写基址值 → 条目变为有效

**同周期依赖检测：**
- 前序指令修改了当前指令的基址寄存器 → 阻塞查找
- 保证多条译码指令之间的数据一致性

---

## P13 Tracing Map 更新与失效

**回写更新：**
- 装入-存储部件完成地址计算后，基址值回写至 Tracing Map
- 严格序列号匹配：回写序列号 ≠ 条目当前序列号 → 拒绝

**失效机制：**

| 场景 | 范围 | 触发条件 |
|------|------|---------|
| 寄存器修改 | 单条目 | 非立即数加减的指令写入该寄存器 |
| 分支预测错误 | 全部 | 检测到分支误预测 |
| 异常/回滚 | 全部 | ROB 回滚或流水线冲刷 |

**正确性保证：** 映射值来自实际回写（非预测），20 个程序页面命中准确率均为 **100%**

---

## P14 分发阶段旁路与 LSU 重试路径执行

**分发阶段：**
- Tracing Map 命中的装入指令**不分配发射队列槽位**
- 仅写入 ROB + LDQ，预测虚拟地址直接写入装入队列
- 即使发射队列满，命中的装入仍可分发（不受反压）

**装入-存储部件执行（复用重试路径）：**
- 重试路径原本用于 D-TLB 未命中后的重新转换
- Tracing Map 命中的装入在 LDQ 中地址已有效 → 恰好满足重试路径选择条件
- **无需新增额外的 D-Cache 访问端口**
- 按年龄优先选择最老的满足条件的 LDQ 条目执行

## P15 立即数偏移融合——问题

**问题：** 循环体中 addi 修改基址寄存器 → 映射条目失效 → 覆盖率骤降

```c
for (int i = 0; i < N; i++) {
    int val = array[i];   // ld a0, 0(s1)    ← 命中
    s1 = s1 + 4;          // addi s1, s1, 4  ← 条目失效！
    // 下一迭代
    int val = array[i];   // ld a0, 0(s1)    ← 未命中，需重新等待回写
}
```

每次迭代：条目在 **有效 → 失效 → 等待回写 → 有效** 中反复切换

> 【插入图 3.13：循环步进访存模式示意图】

## P16 立即数偏移融合——解决方案

**思路：** addi/mv 不使条目失效，将偏移累积到基址值中

```
检测到 addi rs, rs, imm 且 Tracing Map[rs].Valid:
    Base_value += imm        ← 偏移累积，条目保持有效

检测到 c.mv rd, rs 且 Tracing Map[rs].Valid:
    Tracing Map[rd] = Tracing Map[rs]   ← 映射传播
```

支持三类指令：同寄存器自加 addi / 不同寄存器 addi / 压缩移动 c.mv

## P18 偏移融合的内在机制分析

从 Tracing Map 更新次数角度分析覆盖率提升的原因：

| 指标 | 无 ADDI | 有 ADDI | 变化 |
|------|---------|---------|------|
| 装入回写更新次数 | ~1041 万 | ~825 万 | −20.8% |
| 新增 ADDI 偏移更新 | 0 | ~894 万 | — |
| 总更新次数 | ~1041 万 | ~1718 万 | +65.0% |

- 回写更新减少：条目不再因 addi 反复失效重建
- ADDI 更新增加：立即数加法从"失效事件"变为"轻量级偏移累积"
- 总更新增加 = 条目在更长时间窗口内保持有效

## P19 SAB 冲突预检测——问题与方案

**问题：** 装入提前执行 → 可能先于前序存储 → 内存序违例 → 微异常回滚

例：h264ref 仅开 Tracing Map 时 IPC **下降 3.94%**

**SAB（Store Address Buffer）方案：**

1. 存储指令在分发阶段，若基址被 Tracing Map 命中 → 预测地址写入 SAB
2. 加速的装入进入 LSU 前 → 与 SAB 中所有存储地址比较
3. 冲突 → 装入降级为常规路径，等待冲突存储完成

**SAB 结构：** 4 级移位寄存器 × 2（发射宽度），每条目 43 bit，总计 **344 bit**

## P21 推测式唤醒扩展

**问题：** BOOM 原有推测唤醒仅覆盖从发射队列发射的装入，绕过发射队列的装入走重试路径 → 不被覆盖 → 依赖指令无法提前唤醒

**扩展：** 重试路径的装入在 S1 阶段也触发推测式唤醒

本文提出了一种跟踪基址的装入延迟隐藏机制，基于 BOOM V3 处理器设计实现并在 FPGA 平台上验证：

   - 立即数偏移融合将覆盖率提升至 44.47%

   - SAB 使 15/20 程序微异常低于基线
   - 推测式唤醒扩展贡献 +0.60% 额外 IPC 提升

   - 20 个 SPEC CPU 基准程序，MediumBOOM 配置
   - 实现 **2.85% 平均 IPC 提升**，硬件开销可控
