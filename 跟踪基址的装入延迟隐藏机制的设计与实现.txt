研究背景
• 基于 RISC-V 开源处理器BOOMv3[1]运行部分SPEC CPU 2006 [2]和SPEC CPU 2017 [3]基准程序，提交的装入指令的占比大多在20%到30%间，实测平均 25.3%。

研究背景
• 装入指令位于数据依赖链根部，延迟沿依赖链逐级传播
• 即使 L1 D-TLB 和 L1 D-Cache 都命中，发射队列排队延迟仍是关键瓶颈：
从进入发射队列到数据写回，最佳情况仍需 5 个周期。
即使开启推测式唤醒，依旧会使得两个周期内的依赖指令推迟执行。

研究背景
• 如果能提前获取装入指令的装入地址，就能减少依赖指令产生的气泡。
• 在分发时直接绕过发射队列，使得装入指令提前访问装入-存储部件，降低装入指令延迟。
如果不开启推测式唤醒，相比基准实现能对两个周期内的指令产生一周期延迟降低的收益。

相关工作
相关工作——访存地址预测
• 基本思想：对装入指令的访存地址进行预测，在实际访存地址就绪前，提前访存获得数据。
• 推测性方案相关工作：Zero-Cycle Loads [4] 、SLAP [5] 、CAP [6]等。
• 特点：均以 PC 为索引，推测性预测，如果出现误预测需回滚。

相关工作——访存地址预测
• 基本思想：对装入指令的访存地址提前解析，提前访存以获得预测值。
• 非推测性相关工作如： Constable [7] 、Load Slice Core [8] 、 Register Tracking [9]等。
• 特点：命中即正确。以寄存器编号为索引，或通过硬件提前调度符合条件的装入指令。

相关工作——存储相关性预测 
• 基本思想：预测装入指令的访存地址是否与存储指令的访存地址相关，避免内存序违例。
• 相关工作：LWT [10] 、Store Sets [11] 。
• 特点：使用 PC 作为索引。基于历史统计预测存储相关性。

相关工作——推测式唤醒
• 基本思想：将装入指令的依赖指令提前推测式唤醒，降低依赖指令延迟。
• 相关工作：Selective Replay [12] 、Criticality Predictor [13] 。
• 特点：根据目标寄存器编号在发射队列提前唤醒指令。


访存地址预测模块
• 核心观察：
1）当装入指令完成执行回写时，基址值可以缓存在译码阶段可访问的映射表中
2）后续使用相同基址寄存器的装入指令，在译码阶段即可直接获取地址
• 思路：在译码阶段维护寄存器 ，缓存基地址的映射表（Tracing Map），命中的装入指令绕过发射队列和读寄存器阶段，直接进入访存子系统。
• 特性： 确定性地址获取，命中即正确，无需错误恢复。

访存地址预测模块
• Decode阶段查询tracing map。如果命中则携带vaddr信息进入dispatch阶段，在分配表项直接写入地址，绕过发射和读寄存器阶段。
• 如果未命中且未处于等待状态，则将对应表项置为等待状态， 携带seq_id正常进入流水线。在读完寄存器后，seq id匹配情况下将寄存器值写入tracing map中。

访存地址预测模块
 有效条目计算 𝑉𝑎𝑑𝑑r=𝐵𝑎𝑠𝑒𝑉𝑎𝑙𝑢𝑒+𝐼𝑚𝑚𝑂𝑓𝑓𝑠𝑒𝑡。
 表项更新优先级：全局无效 > 目的寄存器写入无效 > 目标寄存器写回更新
 同周期对表项的无效会阻塞对该有效表项的命中，只能设置等待状态。

访存地址预测模块
 命中的装入指令在分发时绕过发射队列，直接将vaddr写入LDQ中，将is_virtual置位。
 在LSU中复用load_retry路径（出现tlb miss的装入指令的执行路径）执行。

访存地址预测模块
 只有处于等待状态且序号相同时才能更新条目并将有效位进行置位。
 避免出现了在等待过程中被无效后，又重新被新的指令置为等待状态时旧指令的值错误覆盖表项。

立即数加减累积偏移优化
• 问题：循环体和数组访问中 addi 修改基址寄存器会导致映射条目失效，进而导致覆盖率骤降，每次迭代条目在“有效 → 失效 → 等待回写 → 有效”中反复切换。
• 方案：跟踪寄存器的立即数加减结果，addi/mv 不使条目失效，将偏移累积到基址值中。

立即数加减累积偏移优化
 有效条目addi/mv指令，将计算值写入到目标寄存器并标记有效。
 等待条目addi指令如果源和目的寄存器相同，将偏移值累积value表项中。
 等待条目返回写回结果时将累积值和写回值相加，写入value表项中。

立即数加减累积偏移优化
 优先级排序：
 1）因异常或分支预测错误等导致的所有寄存器失效。
 2）不可跟踪写入导致的目标寄存器失效。
 3）立即数加减修改的目标寄存器值。
 4）装入-存储部件回写目标寄存器的值。
 5）等待回写状态立即数加减修改的相同寄存器值。

存储-装入冲突检测模块
• 装入指令提前执行，其执行顺序可能先于前序存储，进而可能触发更多的内存序违例。
• 通过让存储指令同样访问Tracing Map提前解析出地址，在分发阶段存储地址和对应STQ序号，让被加速的装入指令查询冲突情况，降低内存序违例的可能性。
存储-装入冲突检测模块
• 将SAB（Stroe Address Buffer）模块设置在进入LSU之前，对于预测会产生冲突的装入指令，在写入表项时将对应STQ序号也写入到LDQ中。
• 存储指令在访问STQ获得STQ序号后，将存储地址和STQ序号写入到SAB条目中。
存储-装入冲突检测模块
• 和同周期先序存储指令产生冲突的装入指令降级为普通装入指令，避免反复访问LSU。
• 和SAB条目比较时，选择最近出现冲突的存储指令的STQ序号写入LDQ中。

存储-装入冲突检测模块
• LDQ额外存储依赖的STQ序号表项。
• 在选择LDQ的条目访问D-TLB和D-Cache时，在原先的选择条件下再增加一个判断对应依赖STQ条目是否已经获得有效的物理地址，只有不依赖STQ条目或依赖条目满足条件才能被选择。

推测式唤醒扩展
• BOOM 原有推测唤醒仅覆盖从发射队列发射的装入，绕过发射队列的装入指令走retry路径，不会被覆盖，因此依赖指令无法提前唤醒。
• 通过让重试路径的装入指令在 S1 阶段也触发推测式唤醒，能进一步缩短依赖指令的延迟。
推测式唤醒扩展
• 由于D-TLB和D-Cache等资源互斥，选择逻辑能保证retry路径和从地址生成单元获得的装入指令只有唯一的装入指令被选中。
• 除了初始的选择逻辑，其余逻辑都可以复用。

实验结果——资源开销分析
	理论开销：Tracing Map表的表项包含1 bit的有效位、1 bit的等待位、6 bit的等待序号以及40bit基地址字段，一个条目的存储开销为48 bit。一共32个条目，存储开销为1536 bit；SAB功能中一个条目内有效位占1bit、存储队列序号占4bit、移位寄存器的高位地址占38bit，一个条目占43 bit。本设计采取4级的移位寄存器，发射宽度为2，故存储开销为344 bit；装入队列每个条目额外存储依赖的存储队列序号，存储开销为80 bit。总计新增寄存器为1960 bit，即245 Byte的寄存器开销。该开销约占MediumBOOM  V3配置中整数寄存器堆容量（640 Byte）的 38%。

实验结果——资源开销分析
	实际开销统计：LUT 使用量约提高9.89% ，FF 使用量约提高3.16% 
	
工作总结
本文提出了一种跟踪基址的装入延迟隐藏机制，基于 BOOM V3 处理器设计实现并在 FPGA 平台上验证：
1. 提出基于译码阶段寄存器-地址映射的装入延迟隐藏方法。该方案命中即正确，无需错误恢复，并通过立即数偏移融合将覆盖率提升至 44.47%。
2. 设计存储冲突预检测与推测式唤醒扩展机制。SAB 使 15 个程序微异常低于基线；推测式唤醒扩展贡献 0.60% 额外 IPC 提升。
3. 基于 BOOM V3 实现完整方案并在 FPGA 上验证，最终实现 2.85% 平均 IPC 提升，硬件开销可控。

未来工作展望
1. 更宽超标量配置评估：扩展至 3或4发射宽度的 LargeBOOM，发射队列竞争更激烈时收益可能更显著。
2. 与硬件预取机制协同优化：Tracing Map 地址信息可作为预取提示，进一步降低 D-Cache 缺失延迟
3. SAB 冲突检测增强：扩展覆盖窗口，结合 Store Sets 等方法提高检测精度。
